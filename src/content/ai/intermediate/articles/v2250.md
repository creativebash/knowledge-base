# OpenAI Python Library v2.25.0: Introducing GPT-5.4 and New Agent Tools

The OpenAI Python library serves as the official gateway for developers to integrate cutting-edge AI models and features into their applications. Each release often brings new capabilities, model updates, and refinements to the developer experience. Version 2.25.0, released on March 5, 2026, is a significant update that introduces a new flagship model and powerful tools for building more capable AI agents. This article will break down the key features and changes, explaining their practical implications for intermediate-level AI developers and engineers.

## Key Features and Enhancements

This release is headlined by the introduction of a new model and two specialized tools designed to expand what AI agents can accomplish.

### 1. The GPT-5.4 Model

The most prominent addition in v2.25.0 is support for the `gpt-5.4` model. As a successor in the GPT series, it promises advancements in reasoning, instruction following, and overall capability. For developers, accessing this model is as simple as specifying it in the API call.

```python
from openai import OpenAI

client = OpenAI()

response = client.chat.completions.create(
    model="gpt-5.4",  # Specify the new model
    messages=[
        {"role": "user", "content": "Explain the significance of the new tools in v2.25.0."}
    ]
)
print(response.choices[0].message.content)
```

When to consider using `gpt-5.4`:
*   For tasks requiring advanced reasoning or complex multi-step analysis.
*   When building applications where state-of-the-art performance is critical.
*   For experimentation and evaluation against previous models like GPT-4o or GPT-4 Turbo.

### 2. New Agent Tools: `tool_search` and `computer`

A major focus of modern AI development is creating agents that can interact with the world. This release introduces two new tools that significantly augment an agent's capabilities.

**The `tool_search` Tool**
This tool allows the AI model to dynamically discover and understand other tools available within a system or environment. Instead of having a static, predefined list of tools hardcoded into the prompt, an agent can use `tool_search` to query for relevant tools based on its current task. This enables more flexible and scalable agent architectures, where tools can be added or removed without requiring extensive prompt redesign.

**The `computer` Tool**
The `computer` tool represents a step towards agents that can interact with a computational environment. While the exact specifications would be detailed in the API documentation, this typically grants the model controlled access to perform actions like executing code, browsing filesystems (in a sandboxed manner), or manipulating data. This is foundational for building AI assistants that can perform practical, actionable tasks beyond just generating text.

Here’s a conceptual example of how these tools might be used within the Chat Completions API with function calling (parallel tool use):

```python
from openai import OpenAI
import json

client = OpenAI()

response = client.chat.completions.create(
    model="gpt-5.4",
    messages=[{"role": "user", "content": "Find a tool to calculate the median and then run it on this dataset: [12, 5, 7, 18, 5]"}],
    tools=[
        {
            "type": "function",
            "function": {
                "name": "tool_search",
                "description": "Searches for available tools by their capability.",
                "parameters": {
                    "type": "object",
                    "properties": {"query": {"type": "string"}},
                }
            }
        },
        {
            "type": "function",
            "function": {
                "name": "computer",
                "description": "Executes a command or operation in a computational environment.",
                "parameters": {
                    "type": "object",
                    "properties": {"command": {"type": "string"}},
                }
            }
        }
    ],
    tool_choice="auto"
)
# The model would likely first call `tool_search` with a query like "calculate median",
# and upon understanding the available `computer` tool, could then call it with a command to compute the median.
```

## API Refinements and Breaking Changes

Alongside new features, the release includes important changes to the API response schema that developers must be aware of.

### Removal of `prompt_cache_key`

The `prompt_cache_key` parameter has been removed from API responses. This key was previously related to experimental prompt caching features, which allowed for cost and latency savings on repeated prompts. Its removal suggests the underlying caching mechanism has been deprecated or significantly changed. If your application logic depended on reading this field from responses, you will need to update your code. The removal is a cleanup action, simplifying the response object.

**Before (v2.24.0 and earlier):**
```python
response = client.chat.completions.create(...)
cache_key = response.prompt_cache_key  # This attribute may have existed
```

**After (v2.25.0):**
```python
response = client.chat.completions.create(...)
# `response.prompt_cache_key` will no longer be available.
# Relying on it will cause an AttributeError.
```

### Deprecation and Reversal of the `phase` Field

The changelog shows an interesting sequence regarding a `phase` field in message types:
1.  It was initially listed as removed in a feature commit (`remove ... phase field from message types`).
2.  A subsequent bug fix commit (`readd phase`) restored it.

This indicates that the removal was either premature or caused issues in dependent systems. The `phase` field is typically used in streaming responses to indicate the stage of content generation (e.g., `"preparing"`, `"generating"`, `"complete"`). **The key takeaway for developers is that the `phase` field is still present and supported in v2.25.0.** You should not remove your handling logic for it. Always check the official API documentation for the definitive schema.

*   **Internal Schema Fixes:** Corrections to the internal API schema definitions ensure better type safety and accuracy in code generation and validation.
*   **Manual Updates &amp; Chores:** These entries point to internal maintenance, code generation improvements, and reduction of warning messages. For end-users, this translates to a more stable and reliable library with fewer unexpected warnings during development.

OpenAI Python library v2.25.0 is a forward-looking release that balances powerful new capabilities with necessary API hygiene.

**Key Takeaways for Intermediate Developers:**

1.  **New Model on the Block:** `gpt-5.4` is now available for experimentation and use in production systems requiring top-tier performance.
